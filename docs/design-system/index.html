Foundations

Color roles

AccentSpeechNoteDanger

Keep the reader’s existing speech and note colors for textual meaning. Use a darker blue for small interactive text on light backgrounds. Pair every grade and recall color with a label.

Type & direction

صحيح البخاري Sahih al-Bukhari

Use system sans for controls and the existing language-specific fonts for reading. Keep each translation’s direction independent. Preserve Quran script choice, vocalization, line height and user scaling.

Space & focus

Proposed spacing in pixels. Use 8 within controls, 16 between related fields and 24 between groups. Aim for 44 × 44 touch targets and a visible two-pixel focus ring.

Coverage & adoption

What the atlas covers

Desktop and mobile captures come from the local Express app in a signed-out Chrome session. Each parameterized route is sampled with representative content. Several URLs resolve to the same page. Open a capture to see its final path. The atlas also includes the open site menu, search dialog and Quran navigator.

Access and rendering limits

Signed-in notebook editing, token-shared notes, moderation, administrative editing and a live recall session need account or record state. Their templates identify further patterns: note sharing and link previews, moderation queues, bilingual pair management, inline TOC editing and recall assessment. The requests list timed out locally. The selected translation’s introduction and surah URL returned 404. The standalone slideshow displayed its controls with a blank content area.

Shared note · Admin managers · TOC editor · Recall session · Requests list

Route boundaries

Legacy activity URLs resolve to Community. Tafsir, translation and Sharh catalog aliases resolve to Books tabs. Quran-prefixed settings and notebook routes reuse the same views. API, corpus JSON, feeds, file downloads, external sign-in and token-based email actions have no independent component specimen here. The separate native Quran Review client is outside this web atlas.

Components to review in their full workflow

  • Administrative editing. Keep heading fields, move and delete controls beside the affected TOC row. Give merge dialogs an explicit surviving record and a preview of the change. TOC editor · Bilingual pair manager
  • Personal study. Inventory the floating note, anchors, sharing, attachments and Drive status together. Carry the same source identity from reader to note and shared view. Note dialog · Shared notebook entry
  • Active recall. Check hidden words, reveal, assessment, paused sessions and progress summaries together using an account with review history. Assessment dialog · Scheduling settings
  • Contextual assistance. Keep the assistant launcher clear of playback and bottom navigation. Test opening, loading, an unavailable service and returning to the passage. Assistant panel

Suggested adoption order

  1. Reader modes and actions. Pilot the shared controls on one ayah, one tafsir and one hadith. Verify reference continuity and keyboard access at both widths.
  2. Discovery. Align catalog rows, filter state and empty results across Hadith, Sharh and Quran search. Preserve the different metadata each work needs.
  3. Contribution. Align disclosure, editor and save feedback in Community and Notebook. Validate signed-in and administrative flows with suitable accounts before applying those standards.
